# Shalaby Chat — الخطوتان 1 و2

## 1) التقنيات المقترحة

| الجزء | التقنية | السبب |
|---|---|---|
| واجهة المستخدم | React + TypeScript + Vite | تطوير سريع وواجهة تفاعلية مع أنواع تقلل أخطاء البيانات. |
| تصميم الواجهة | Tailwind CSS | بناء شاشة محادثة متجاوبة بسرعة. |
| الخادم وواجهات API | Node.js + NestJS + TypeScript | تنظيم واضح للوحدات والخدمات، مناسب لنمو التطبيق. |
| الاتصال الفوري | Socket.IO | أحداث ثنائية الاتجاه، وإعادة اتصال تلقائية وغرف للمحادثات. |
| قاعدة البيانات | PostgreSQL + Prisma ORM | معاملات وعلاقات وفهارس قوية، مع مخطط قابل للتحديث. |
| التوسع لاحقاً | Redis | مشاركة حالة الاتصال والغرف بين أكثر من نسخة خادم. |
| تخزين الصور لاحقاً | S3-compatible object storage | حفظ الملفات خارج قاعدة البيانات وإرسال روابط آمنة. |

**التدفق المقترح:** React يرسل الرسالة عبر Socket.IO إلى NestJS؛ يتحقق الخادم من الهوية وعضوية المحادثة، ويحفظ الرسالة في PostgreSQL، ثم يبثها للمشاركين. لا تعتمد على البث وحده: الحفظ أولاً يجعل الرسائل قابلة للاسترجاع بعد انقطاع الاتصال.

## 2) مخطط قاعدة البيانات

المخطط الأساسي موجود في [`prisma/schema.prisma`](prisma/schema.prisma). يتضمن المستخدمين والمحادثات وأعضاء كل محادثة والرسائل وإيصالات التسليم والقراءة.

- كل رسالة محفوظة تمثل حالة **Sent**.
- لكل مستلم سجل `MessageReceipt` يبدأ بـ **SENT**، ويتحول إلى **DELIVERED** عندما يستلم جهازه الرسالة، ثم **READ** عند فتحها.
- إيصال منفصل لكل مستلم يدعم المحادثات الجماعية. لا نحتاج تخزين كل حالة كحقل واحد على الرسالة.
- `directKey` اختياري لتمييز محادثة خاصة واحدة لكل زوج مستخدمين؛ أنشئه في الخادم بترتيب UUID ثابت. اتركه فارغاً للمجموعات.
- تحقق في الخادم من أن المرسل عضو في المحادثة، وأن المستلم عضو فيها. هذه قواعد صلاحيات وليست مضمونة بمجرد تعريف الجداول.

### تهيئة وتشغيل Prisma

بعد إعداد مشروع الخادم وتثبيت `prisma` و`@prisma/client`، أضف رابط PostgreSQL إلى `DATABASE_URL` في ملف البيئة، ثم نفّذ:

```bash
npx prisma generate
npx prisma migrate dev --name init_chat
```

لا تضع بيانات الاعتماد الحقيقية في المستودع؛ استخدم متغيرات البيئة.

## الخطوات التالية

بعد اعتماد المخطط، نضيف مصادقة المستخدمين ثم أحداث Socket.IO لإرسال الرسالة وحفظها وبثها. يمكن إضافة الحضور وكتابة الرسائل عبر Redis، وإضافة مرفقات ببيانات وصفية في PostgreSQL وملفات في تخزين كائني، ثم إشعارات Push عبر مزود مناسب.
